# Proven video upload procedure — master v1
Use existing native ProspectVideo; no Canva/Drive embed. Follow docs/CLIENT_PAGE_PLAYBOOK.md section 7 for complete provenance.
1. Optimize approved original MP4 (H.264/AAC, faststart); preserve audio and full recording. Example: ffmpeg -i input.mp4 -c:v libx264 -crf 24 -preset medium -c:a aac -b:a 96k -movflags +faststart output.mp4. Verify actual dimensions, duration, codec and audio using ffprobe.
2. Sample multiple actual frames with ffmpeg; choose a natural flattering frame, optionally add approved restrained text. Save client-specific versioned JPG. Verify visual selection with Brent. Measure bytes and SHA-256 for both files (wc -c, sha256sum).
3. If direct binary transfer unavailable, upload privately to 3P Workspace Drive as temporary bridge and retrieve actual Base64 bytes with connector. Split the encoded MP4 into ordered chunks around 350000 characters, create GitHub UTF-8 blobs, add to feature-branch tree under media/_transfer/<slug>-00.b64 etc. Poster uses separate versioned blob. Never put Base64 in page source or expose Drive link.
4. In scripts/build-proposal-media.cjs append assemble([...ordered chunk filenames], "<slug>-introduction.mp4", measuredBytes, measuredSha256); add matching poster assemble call. Existing function joins, validates, decodes and checksum-checks before emitting public/proposal-media assets. Preserve all prior calls and files. Existing Hand & Stone uses 16 chunks and verified 3983476-byte MP4; its v2 poster is 89179 bytes. These are reference values only.
5. Set video.src and video.poster to /proposal-media/<unique versioned file>. Build and check Verified media log; verify external 200/206 range response, content type, poster, play/pause/seek and audio on desktop/mobile. Native controls, playsInline, metadata preload, no autoplay. Do not publish until approved.
